# 机制图验收

保存 `review.json`，逐项写 `pass`、`fail` 或 `unverified` 和具体观察，不用“检查通过”掩盖未核对项。

| 检查项 | 具体核对 |
|---|---|
| 内容 | 模块数量与名称一致；没有新增模型、数据集、结果或科学结论 |
| 拓扑 | 对照 brief 的每条边，起点、终点、方向、分支与回路都一致；没有额外系统箭头 |
| 语义 | 读/写、训练/推理、损失/数据、冻结/可训练等可区分；图标内部图边不与系统流程混淆 |
| 文字 | 标签逐字核对；缩写、下标、维度、运算符不变；没有模板 ID、原论文标题或水印 |
| 布局 | 无遮挡与误接，放大框对应总图模块，跨组连线留出空白 |
| 风格 | 选定布局与视觉表达可辨认；颜色只表达已说明的语义；黑白缩小仍可理解 |
| 投稿适用性 | 按实际版面缩放看文字与线条；位图分辨率符合目标要求，未声称为可编辑矢量 |
| 文件 | 成图、brief、实际 prompt、参考出处与 review 都存在，能打开 |

目测不能确认的部分标为 unverified。密集文字与数学符号可在后续排版中叠加矢量文字，但必须保留真实生成结果并明确说明处理；不能用改后缀的方式“输出 SVG”。

失败项修复后需要重新检查相关项，保留上一版以便比较。默认最多两次定向修复，是此 skill 的成本控制建议；用户要求继续时按新授权继续。
